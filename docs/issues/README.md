# Issues 工作流

本目录是 `throne` 的缺陷与功能登记册。所有改动都必须先在这里落盘，再评估，再执行。

## 分类

| 类别 | 目录 | 用途 |
| --- | --- | --- |
| BUG | [BUGS.md](./BUGS.md) | 与设计意图不符的行为、错误、崩溃、不一致 |
| FEATURE | [FEATURES.md](./FEATURES.md) | 新增能力、机制、场景、界面 |
| DECISION | [../architecture](../architecture) | 影响架构或规范边界的决定（ADR），沿用 `NNNN-title.md` |

一个改动若同时涉及缺陷与功能，拆成两条互相引用，不要混写。

## 状态

`登记` -> `根因确认` -> `方案评估` -> `实现中` -> `已验证` -> `已关闭`

- 未确认根因的条目不得进入 `方案评估`。
- `已关闭` 必须给出验证命令与结果。

## 硬约束

1. **根因优先**：任何 BUG 必须先写出根因（触发条件、数据流、为什么现有校验没拦住），禁止只改表象。根因未确认前不得提交修复。
2. **禁止兜底**：不允许静默降级。包括但不限于：`try/catch` 吞异常、用 `??` / `||` 掩盖缺失值、`switch` 的 `default` 静默放过未知输入、宽松解析畸形数据、在缺少凭据/指令时回退到默认值。遇到未定义输入应在边界**显式失败**。
3. **文档先行**：动代码前，先在对应登记册写清：现象、根因、影响面、是否涉及兜底、方案、验证方式。评估通过后才实现。
4. **可回放**：涉及模拟行为的改动，必须包含确定性测试或场景回放验证。

## 条目模板

```markdown
### BUG-0000 标题

- 状态：登记
- 是否兜底：是/否
- 位置：path/to/file.ts:line
- 现象：
- 根因：
- 影响面：
- 方案：
- 验证：
```

FEATURE 条目把"现象/根因"替换为"动机/当前差距"。

## 与既有文档的关系

- 模拟规则与架构边界以 [SPEC.md](../SPEC.md) 为准，不在本目录改写。
- 玩法意图以 [DESIGN.md](../DESIGN.md) 为准。
- 进度快照以 [STATUS.md](../../STATUS.md) 为准；本目录只记录逐条事项，不替代 STATUS 的切片规划。
- 提交前验证命令见 [CONTRIBUTING.md](../CONTRIBUTING.md)。
