# ADR 0005：两次决策，共享一段历史

状态：采纳，2026-09-22。

真实 NPC 入口改用独立的连续场景；旧单轮场景和 version 1 存档不改。新局 version 2 在同一个 kernel、事件日志与世界状态中运行。两次御前决策分别在 t=10、100；圣旨五分钟后发出，传递三十分钟，统领考虑五分钟、执行十分钟，回报再传三十分钟。第二次不是重开第一局，也不删除第一道命令。维持部署同样是一道新命令，目标取自已收到的统领回报。

本切片固定两个预先存在的风险：t=60 宫城渗透、t=150 东门仓场袭击。守在相应地点的禁军可阻止当次袭击；第二次成功不能抹掉第一次失守。新的东门目击情报在 t=100 到御前、随第二道圣旨到统领。仍是小场景判定，不是通用战斗/战役系统。当前不增加世界生成或自动关系分值变化。

NPC 身份、动机、关系沿用同一份档案。记忆由已提交的个人决策、已收到的命令、自己的行动观察组成；上次未亲眼见到的宫城结果只能通过之后收到的报告获知。每次调用仍使用隔离 Harness 进程，人物连续性由引擎记录提供，不依赖供应商聊天历史。

普通界面时间线只显示御前已收到的观察与自己发出的命令。收到回报前不暴露统领是否收令、私人选择或世界结果。所有 NPC 输入、简短理由和客观状态只在整局完成后开放。API 提交必须携带 decisionEpisodeId，重试/重复请求不能推进另一个回合。

失败恢复、隐私和持久化边界沿用 [ADR 0004](0004-live-npc.md)：未结束局仍在内存，完成后写盘；重放只读事件，不再调用模型。旧 version 1 记录按旧 reducer 重放。连续场景不演示信使超越；在途相反命令仍由已有 decision-revision 演示覆盖。
